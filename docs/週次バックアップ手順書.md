# Growth OS 週次バックアップ手順書(ハイブリッド方式)

- 最終更新: 2026-10-13
- 方式: SQLiteバックアップ(スクリプト・自動)+ 7-Zip GUI暗号化(手動)+ OneDrive保存(手動)

## 0. 前提

- 対象DB: `prisma/dev.db`(このファイル自体には触れない。読み取りのみ)
- 作業ディレクトリ: `C:\Users\chihiro\OneDrive\デスクトップ\AIの作業場\growth-os`
- ローカル保存先: `C:\Users\chihiro\AppData\Local\GrowthOSBackups`
- OneDrive保存先: `C:\Users\chihiro\OneDrive\GrowthOSBackups`
- 既存の`GrowthOSBackups`内ファイルは削除・上書きしない。保存世代数のルール変更は今回は行わない(別工程で検討)。

## 1. SQLiteバックアップの実行(自動)

1. PowerShellを開く。
2. 作業ディレクトリに移動する。
   ```
   cd "C:\Users\chihiro\OneDrive\デスクトップ\AIの作業場\growth-os"
   ```
3. バックアップスクリプトを実行する(引数なし=本番DB対象)。
   ```
   node backup-sqlite.cjs
   ```
4. 出力の**最後の行**を確認する。
   - `RESULT=SUCCESS` → 整合性確認(全13テーブルの件数・ハッシュ一致、`integrity_check`、`foreign_key_check`)も含めて合格。次に進む。
   - `RESULT=SUCCESS`以外(`RESULT=FAILURE`やエラー表示) → **停止**。「5. エラー時の停止条件」へ進み、暗号化・OneDrive保存は行わない。

   補足: このスクリプトは、整合性確認に合格した場合のみ成功ログ(`.log.json`)を書き込む設計のため、`RESULT=SUCCESS`の表示そのものが「バックアップ成功かつ整合性確認済み」の証拠になる。

5. `C:\Users\chihiro\AppData\Local\GrowthOSBackups` を開き、一番新しい `dev_backup_<日時>.db` と、同じ日時の `.log.json` ができていることを目で確認する。

## 2. 7-Zip GUIでの暗号化

1. 手順1で作った最新の `dev_backup_<日時>.db` を右クリックする。
2. メニューから **7-Zip → 圧縮...** を選ぶ。
3. 表示された画面で以下を設定する。
   - アーカイブ形式: **7z**
   - 暗号化方式: **AES-256**
   - パスワード: 入力欄と確認入力欄の両方に、既存の管理用パスワードを入力する。
   - **「ファイル名を暗号化」にチェックを入れる。**
4. 「OK」で作成する。同じ日時名の `.7z` ファイルができる。
5. **既存の`.7z`ファイルを上書きしない**(ファイル名が自動で日時入りになるため、通常は衝突しない)。

パスワードはこのGUI画面にのみ入力する。コマンド・チャット・メモ・ログには一切入力・記録しない。

## 3. アーカイブの検証(暗号化が正しくできたかの確認)

1. 作成した `.7z` を右クリック → **7-Zip → アーカイブをテスト**。
2. パスワード入力を求められたら入力し、結果が「Everything is Ok」等、エラーなしの表示であることを確認する。
3. エラーが出た場合 → **停止**。OneDriveへはコピーせず、「5. エラー時の停止条件」へ。

## 4. OneDrive保存

1. **暗号化済みの`.7z`ファイルだけ**を `C:\Users\chihiro\OneDrive\GrowthOSBackups` にコピーする。
2. **平文の`.db`ファイル・`.log.json`・パスワード関連ファイルは絶対にOneDrive側へコピーしない。**
3. **既存ファイルを上書きしない**(同名ファイルがある場合は上書き確認が出るので「はい」を押さず中断し、状況を確認する)。
4. ブラウザで `https://onedrive.live.com` を開き、`GrowthOSBackups` フォルダに入って、今コピーした`.7z`ファイルが表示され、更新時刻が「数分前」等になっていることを確認する。

## 5. エラー時の停止条件と対処

| 発生箇所 | 停止条件 | 初心者が確認できる対処 | 再実行してよい条件 | Claude Codeへ報告する情報 |
|---|---|---|---|---|
| 1. バックアップ | `RESULT=SUCCESS`が出ない | 既存バックアップ・DBには触れず、画面の出力をそのまま保存する | 原因が分かり、DB側に問題がないと確認できた場合 | 出力メッセージ全文(パスワード等の機密情報は含まれない前提だが、念のため目視で確認してから共有する) |
| 2. 暗号化 | パスワード入力ミス、「ファイル名を暗号化」の付け忘れ | 作成した`.7z`を削除し、手順2を最初からやり直す(元の`.db`バックアップには影響しない) | いつでも(暗号化のやり直しは安全) | 発生した画面のエラー文言(パスワードは含めない) |
| 3. アーカイブテスト | テスト結果がエラー | その`.7z`はOneDriveにコピーしない。削除して手順2からやり直す | 手順2をやり直した後 | テスト結果の表示内容(パスワードは含めない) |
| 4. OneDrive保存 | コピー失敗・容量不足・同名ファイルの上書き確認が出る | コピーを中止し、ローカルの`.7z`はそのまま保持する(ローカル側は無事なので再試行可能) | 原因(容量・ファイル名重複等)が解消した場合 | エラーメッセージ、対象ファイル名・サイズ(内容は共有しない) |
| 4. OneDrive保存(Web反映) | Web上で反映されない | 数分待って再確認する | 反映が確認できた時点で完了 | 待機時間、再確認した時刻 |

いずれの場合も、既存のバックアップファイル・本番DB・OneDrive上の既存ファイルは変更・削除しない。

## 6. 秘密情報の保護

- パスワードは手順書・ログ・チャット・コマンド履歴に記載・入力しない(7-Zip GUIのパスワード入力欄にのみ入力する)。
- パスワードの取得・表示・再生成は、本手順の実施中には行わない。
- エラー時にClaude Codeへ報告する内容には、パスワードや個人データ本文を含めない。

## 7. 毎週の操作(初心者向け・簡潔まとめ)

1. PowerShellで `growth-os` フォルダに移動し、`node backup-sqlite.cjs` を実行 →「`RESULT=SUCCESS`」を確認。
2. できた最新の`.db`ファイルを**右クリック→7-Zip→圧縮**→7z形式・AES-256・パスワード2回入力・「ファイル名を暗号化」にチェック→作成。
3. できた`.7z`を**右クリック→7-Zip→アーカイブをテスト**→エラーなしを確認。
4. その`.7z`だけを OneDrive の `GrowthOSBackups` フォルダにコピー(平文`.db`はコピーしない)。
5. ブラウザで onedrive.live.com を開き、ファイルが反映されているか確認。
6. 完了。カレンダー等に「成功/失敗」だけメモする(内容やパスワードは書かない)。
