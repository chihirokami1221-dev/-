# Growth OS 週次バックアップ手順書(Turso本番DB用)

- 最終更新: 2026-10-13
- 対象: Turso上の本番データベース(**本番DB自体は未作成。本番用の接続先・保存先は未設定**)
- 方式: Embedded Replica同期(`@libsql/client@0.18.0`、独立検証環境`turso-verify/`)+ 7-Zip GUI暗号化 + OneDrive保存

既存のローカルSQLite用手順書(`docs/週次バックアップ手順書.md`)はそのまま維持し、本手順書はTurso本番DBが本番稼働を始めた後に使用する。**対象・保存先が別物であり、両方を実施する必要がある場合は混同しないこと。**

## 0. 前提(未設定の部分を明記)

- 本番用Tursoデータベースは**未作成**。本手順の`TURSO_PROD_DATABASE_URL`・`TURSO_PROD_READONLY_TOKEN`は、本番DB作成後に発行される値であり、**現時点では未設定**。
- 同期スクリプトは`turso-verify/turso-sync-backup.cjs`(`@libsql/client@0.18.0`、メインアプリの依存関係とは独立)。
- このスクリプトを実行すると、**ローカルに暗号化前の平文バックアップファイル(`.db`)が生成される**。暗号化するまでは、このファイルにも実データが含まれる点に注意する(既存のSQLite用手順と同様の扱いが必要)。

## 1. Turso同期の実行

1. PowerShellを開き、作業ディレクトリに移動する。
   ```
   cd "C:\Users\chihiro\OneDrive\デスクトップ\AIの作業場\growth-os\turso-verify"
   ```
2. 本番用の接続情報ファイル(例: `.env.turso-prod.local`。**本番DB作成後に、ご自身で安全に作成**)を使い、同期スクリプトを実行する。
   ```
   node --env-file=../.env.turso-prod.local turso-sync-backup.cjs
   ```
3. 出力の**最後の行**を確認する。
   - `RESULT=SUCCESS` → 整合性確認(13テーブルの件数・内容ハッシュ一致、`integrity_check`)も含めて合格。次に進む。
   - `RESULT=SUCCESS`以外 → **停止**。「5. エラー時の停止条件」へ進み、暗号化・OneDrive保存は行わない。

   補足: このスクリプトは、以下を自動で行い、全て合格した場合のみ`RESULT=SUCCESS`を返す。
   - リモート(Turso)との直結接続による件数・内容ハッシュの取得
   - Embedded Replicaへの同期
   - 同期完了・接続クローズ後のスナップショットコピー
   - WALチェックポイントによる単一ファイルへの統合(本体ファイル1つだけで内容を再現できる状態にする)
   - リモートとローカルの件数・内容ハッシュの一致確認(不一致時は1回だけ再比較し、比較時点のずれか本当の不一致かを区別する)

4. 生成されたバックアップファイル(`C:\Users\chihiro\AppData\Local\GrowthOSBackups\turso-sync\`内の`*_snapshot_*.db`、および同名の`.log.json`)を確認する。**この`.db`ファイルは平文(未暗号化)である。**

## 2. 7-Zip GUIでの暗号化

既存のSQLite用手順(`docs/週次バックアップ手順書.md`)と同じ手順を、Turso用のバックアップファイルに対して行う。

1. 手順1で作った最新の`*_snapshot_*.db`を右クリック → **7-Zip → 圧縮...**
2. アーカイブ形式: **7z**、暗号化方式: **AES-256**、パスワード2回入力、**「ファイル名を暗号化」にチェック**。
3. 作成された`.7z`を右クリック → **7-Zip → アーカイブをテスト** → エラーなしを確認。

## 3. OneDrive保存

1. **暗号化済みの`.7z`ファイルだけ**を、Turso用の保存先フォルダ(例: `C:\Users\chihiro\OneDrive\GrowthOSBackups\turso\`。既存のSQLite用フォルダとは分ける)へコピーする。
2. 平文の`.db`・`.log.json`は絶対にOneDriveへコピーしない。
3. ブラウザで`https://onedrive.live.com`を開き、ファイルが反映されていることを確認する。

## 4. ローカルの平文バックアップの扱い

- 暗号化・OneDrive保存が完了したら、ローカルに残っている平文の`*_snapshot_*.db`・`*_replica_*.db`・`.log.json`は、**手動で削除するか、暗号化済みアーカイブと同じ場所に残さない**ことを推奨する(現時点では自動削除の仕組みは導入していない)。

## 5. エラー時の停止条件

| 発生箇所 | 停止条件 | 対処 |
|---|---|---|
| 1. Turso同期 | `RESULT=SUCCESS`が出ない | 出力をそのまま保存する。既存バックアップ・本番DBには影響しない(スクリプトは読み取り専用同期のみ)。原因調査は別途行う |
| 2. 暗号化 | パスワード入力ミス等 | 作成した`.7z`を削除し、手順2をやり直す |
| 2. アーカイブテスト | エラー | その`.7z`はOneDriveにコピーしない。手順2からやり直す |
| 3. OneDrive保存 | コピー失敗・同名ファイルの上書き確認が出る | コピーを中止する。既存ファイルを上書きしない |

## 6. 復元方法と注意事項

1. 暗号化アーカイブを展開し、平文の`.db`スナップショットを取り出す。
2. `turso-verify/`内のスクリプト(Prisma/`@libsql/client`経由)で、このファイルの内容を対象のTurso DBへ書き込む(読み取り元がローカルファイルになる以外は、既存の移行リハーサルと同じ仕組み)。
3. 書き込み後、件数・内容ハッシュを再比較し、復元が正しく行われたことを確認する。
4. **注意**: この復元手順で書き込み先DBの既存データは上書きされる。復元先を間違えないよう、接続先URLを必ず確認すること。
5. 復元のend-to-endテストは、本番DBではなく検証用DB(`growth-os-migration-test`等)で事前に行うこと。
