# トークン節約ルール

growth-osプロジェクトで作業する際は、以下を意識する。

1. **修正はまとめて依頼・実行する**
   小さな変更を1つずつビルド・確認せず、関連する複数の修正をまとめてから
   `npm run build` とサーバー再起動を1回で行う。

2. **検証の厳密さはリスクに応じて変える**
   - DBスキーマ変更・データ移行 → バックアップ+件数確認を必ず行う
   - 見た目の微調整(文言・レイアウト)→ ビルド成功の確認だけで十分

3. **PowerShellでの確認は最小限に**
   - 日本語を含むデータをコンソールに直接出力しない(文字化けして見えるだけで実データは壊れていないことが多い→疑ったらファイル出力+Readで確認)
   - 同じ確認を何度も繰り返さない

4. **話題が変わったら新しい会話を始める**
   機能がひとつ完成して区切りがついたら、次の話題は新しいセッションで始める。
